# 三义剧本制作前整理 SOP V1.3

**用途：**从指定版本的完整正文中筛出**需要在出图／出视频之前先设计并归档**的资产，并交代三件事：为什么要预制、预制成什么形态、和正文哪里对得上。
**不适用：**续写、改稿、分镜、出图、视频生成、立项评分。V1.1、V1.2 留档，不覆盖旧版。

## 0. 相对 V1.2 的变化

V1.2 只有一道入库门槛（复用 + 同一性漂移），会漏掉两类资产：一次性出现、但提示词很难稳定生成的画面；反复比对的证据版式只有靠"拿不准降 B"来兜底。V1.3 改为：

1. **三道入库门**：R 复用、E 证据比对、D 难生成。通过任一门即入 A，并记录通过的是哪一道。
2. **A 级必须写预制形态**：只写"需要做出什么、必须包含哪些正文已写元素"，不设计外观，不写提示词。
3. **三种运行模式**：`full` 全量、`delta` 增量、`preview` 预研。稿子还在改时不再硬出一份会过期的正式清单。
4. **校验脚本与命名登记**：数量对不上、称谓漂移（如同一职业两种叫法）、引用不存在的场次，在渲染前就能发现。

## 1. 输入与交付

只以用户指定正文和本轮确认事实为准；项目记忆仅辅助同一性，不覆盖正文。旧稿与其他项目不得混入。每次交付同版本号的 JSON、MD、单文件 HTML；声音建议默认包含，上一版已有的音色与 BGM 在新版中保留并复核。

| 模式 | 何时用 | 要求 | 交付差异 |
|---|---|---|---|
| `full` | 正文已定稿，首次整理 | 完整读取指定范围 | 正式清单 |
| `delta` | 已有旧清单，正文有改动或集号重排 | 旧清单 JSON + 新正文 | 在正式清单中增加"相对旧版变化"区和新旧集号对照 |
| `preview` | 正文仍在重写，需要先让设计提前开工 | 只提取标记为稳定的项 | 首页显示"预研／非正式"，数量不作为交付数字 |

模式细则见 `references/delta-and-preview.md`。

## 2. 先判"该不该预制"

每个候选项按顺序问：

1. 它是不是真正的**镜头内可完成**项（一次性表情、普通受伤、一次吐血、普通手持物、过场特效）？是，且不属于难生成类型，直接记 C。
2. **R 复用门**：它是否在多个镜头或多集出现，重生成会不会造成观众可见的漂移（脸、服装、空间、文字、证物状态）？
3. **E 证据门**：后续是否要比对同一物的纹样、伤痕、文字、位置、页序或持有人？若是，即使镜头少，也保留"证据版式"，并写明比对点。
4. **D 难生成门**：即使只出现一两次，它是否属于难生成类型（文字与版式、复杂空间／机关、非常规姿态、多步特效／变形、群像与精确数量、非常规形态），并且能写出**最可能出的错**（`failure_mode`）？若是，作为 D 门入库，默认只做"轻量参考"。

| 层级 | 定义 | 交付位置 |
|---|---|---|
| A 预制主资产 | 通过 R、E、D 任一门 | 主清单，计数，并注明通过的门 |
| B 场景级参考 | 只在一段戏内需统一方位、灯位、页序、桌面摆位或服装状态 | 非预制项／所属场景备注，不计数 |
| C 镜头内生成 | 单次动作、表情、伤妆、普通手持物、一次性特写、过场特效 | 非预制项简记或不列，不计数 |

**防滥用：**"剧情重要""给了一次特写""服装可能不同"都不构成入库理由。D 门不是"看起来难"，必须同时满足：属于类型表中的某一类，并且写得出具体失败表现。难判断时：

- R、E 拿不准 → 降 B 并标待确认；
- D 拿不准 → 看失败成本：失败会被观众一眼看出（乱码文字、机关方位错、数量错）→ 以 `weight: light` 升 A 并标待确认；否则降 B。

难生成类型表、判断问答和例子见 `references/gates-and-taxonomy.md`。

## 3. 预制形态（A 级必填）

每条 A 写 `deliverable_spec`：`forms`（做什么）、`must_include`（必须包含的正文已写元素）、`weight`（`light` 一张参考页或一组关键帧，`full` 完整资产包）。形态取值：

| 形态 | 含义 |
|---|---|
| `character_sheet` | 角色基型参考（脸、体型、标志性局部） |
| `form_sheet` | 状态／形态对照 |
| `pose_pack` | 非常规姿态／动作参考组 |
| `space_plan` | 空间平面与出入口、机位约束 |
| `layout_pages` | 文字／界面／表格版式页 |
| `evidence_sheet` | 证物固定特征与编号表 |
| `fx_keyframes` | 特效／变形关键帧母版 |
| `photo_ref` | 照片、证件照类参考 |

只写"做什么"和"必须包含什么"。外观、配色、款式正文没写的，标 `待设计`，不得补全。

## 4. 分类口径

### 角色

核心角色长期出场的基型通常入 A。只有反复出现、观众需要认出且外观必须固定的换装、遮挡、伪装、灵魂、变身等特殊形态，才增加制作状态卡。状态卡记录正文已写的服装、遮挡、伤妆、可见特效与切换场次；没写款式就标待设计。办公室、手术、审讯是地点／剧情功能，**不是换装证据**。普通虚弱、单片段吐血、短暂淤青、即时表情不建状态卡。

反复出现的受害者、群演等"只出现几集但脸要对得上"的角色，若后续有比对（遗照、证件照、案卷照片）按 E 门处理，不因"配角"自动排除。

### 场景

跨集复用，或单集多镜头必须维持平面、入口、机关位置、破损状态的空间入 A。固定机关、隐藏门、电梯、桌面陈设并入所属场景，不重复计为道具。一场式通用空间无后续复用，列 B 或 C。场景锚点只写可见、可核对的结构与物件。

某场景由多个子空间构成（如同一机构的几间屋）时，作为一个场景包，在 `space_plan` 中写清相互方位。

### 道具、规则视觉、版式包

- 同一证物跨场追踪、反复特写比较、文字版式／损坏状态影响推理，才单独入 A。
- 只是"同类针筒／刀"，不得无证据合并成同一实物；可以做统一外形规范，同时另记每件的证物编号待确认。
- 能力特效、数值界面等反复调用的效果归**规则视觉**，不叫手持道具。
- 文书、短信、屏幕界面、表格、标签等**文字载体**归**版式包**（`asset_type: 版式包`）：一次设计多页，避免每次生成时文字乱码或页序漂移。
- 反复出现的特殊生物或半透明形态归**形态素材**（`asset_type: 形态素材`）。
- 音色与 BGM 是单列的复用声音库，不混入视觉资产数量。

### 条件可见锚点

有些特征默认看不见，只在特定镜头出现（如被毛发遮住的标记、只在某一角度可见的伤痕）。在锚点上写 `visibility: conditional` 与 `visible_when`，并在连续性备注里写明其他镜头不得露出。避免后期因为"没人知道这条规则"而穿帮。

## 5. 执行流程

1. 锁定正文范围与运行模式，先建立场次索引（`meta.scene_index`）；重复集号用标题临时区分，不擅自替编剧重编集数。
2. 建 `naming_registry`：每个核心角色／物件的规范名、可接受别名、禁用写法。后续整理一律使用规范名。
3. 对每个候选项记录：出现集／镜头、需要锁定的同一性、后续用途、通过的门或降级理由。
4. 对角色检查基型与必要状态；对场景检查空间复用；对道具检查证据链；对文字载体和特殊形态做一轮 D 门扫描。
5. 去除"只因特写一次"或"可能会换装"的假资产。从旧版清单复核时，列出保留、合并、升级、降级、移除并写理由。
6. 资产风险只报同一性、位置、状态和持有人问题；普通剧情逻辑疑问不借资产清单扩张。
7. 输出 JSON → 运行 `validate_inventory.py` → 修到 0 个错误 → 渲染 HTML → 检查首页。

### 常见边界情形（实测补充）

1. **制作标注里的视觉描述。**正文里的 PS 或括号里的制作说明（如某个形态、镜头限制）可以作为 `must_include` 的来源，但必须在 `needs_confirmation` 写明“来源为制作标注，请确认是否作为正式设定”；不得当作已确认事实。
2. **范围内只有名字或声音、没有画面的对象。**不预制，记为非预制项，去向写“暂缓：范围内无出镜”，并写 `revisit_when`。正文只提到、没写可见形态的效果（如只有一句话的界面）写“暂缓：可见形态未写明”。
3. **范围切分带来的伏笔型证据。**范围内只出现一次、无法判断后续是否比对的项（如一个特写的手、一支针筒），按“拿不准降 B”处理，并在 `revisit_when` 写重评条件；不引用范围外的内容。下一轮用 `delta` 模式复核。
4. **场次编号。**无标头的转场画面用字母后缀（`E04-2b`）；一个标头含多个地点时用后缀拆开（`E08-1a`、`E08-1b`）。
5. **规则视觉的合并粒度。**同一种视觉语言只建一条（如多处共用的“开合”动作），不按出现位置拆分；效果之间互相独立、需要分别设计时才分开。判断标准：设计端是否需要做两套。
6. **低重要度但反复出现的 R 门资产。**如背景群演、没有正面画面的角色，允许 `weight: light`，但必须写 `weight_note` 说明理由。
7. **命名登记的禁用写法。**写成带上下文的错误短语，不写常用词本身，避免清单自己的正常用词被误报。

## 6. 声音建议（默认提供）

声音建议随资产清单一并交付，不再等用户额外要求；用户明确不需要时，在 `meta.audio_skipped` 写 `true`。声音库不计入视觉资产数量，所有建议标为待导演／声音指导确认，不得当作正文事实。

1. **人物音色**：每个有台词的角色一条，分主角、配角、群声。写声线方向（音域倾向、质地、语速）、状态切换（带来源场次）、避免事项。不模仿在世演员，不以未确认的外貌推导声线。没有角色资产的发声者（合声、播音员、群众呼喊）按群声写。
2. **固定 BGM**：判断哪些场景或规则视觉会反复出现、适合整季使用同一首固定主题（`recurrence: 固定主题`），哪些只服务某一段（`段落氛围`），哪些不适合配乐。每首写适用场景（`scene_ids`）、风格与配器、BPM 或节拍感、进入与退出点、不能遮盖的台词、避免事项。
3. **场景与固定 BGM 对照**：每个场景一行，没有固定 BGM 的明确写出。
4. **按集调用点**：具体到哪一场、何时进何时退、配什么环境声或拟音；不配 BGM 的段落留空 `bgm_id` 并写拟音替代。
5. 不用具体成品歌曲名；经文、歌曲、现成录音标授权待确认，并给原创替代方向；关键证据台词前优先留静默或环境声。

## 7. 验收

- 校验脚本 0 个错误，警告逐条看过。
- HTML 首页直接显示：入库门槛、A 级数量（按 R／E／D 分门）、非预制项数量与去向、待确认数；`preview` 模式显示"预研／非正式"。
- 主清单中每条都能回答"为什么值得预制、通过哪道门、预制成什么"。
- 跨集角色、证据与场景状态能回查到正文；无来源的猜测只出现在待确认栏。
- JSON 可解析，HTML 自包含且能预览；上一版已启用的音色／BGM 在新版中仍完整存在。
- MD 摘要与 HTML 数量一致。
