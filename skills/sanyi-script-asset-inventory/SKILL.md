# 三义剧本制作前整理 Skill V1.3

## 目的与边界

把**已确认的剧本正文**整理成可交接给设计与制作的资产事实表，交付 JSON、Markdown 和单文件 HTML。**声音建议默认一并提供**：主角与配角的音色声线、可用固定 BGM 的场景及每首 BGM 的建议；用户明确不要时，在 `meta.audio_skipped` 写 `true`。

**清单只写与制作和资产画面有关的内容**：要做什么、必须出现什么、可见锚点、状态、容易出错的地方、待确认事项。不写剧情功能、人物心理、情节解释（如“推理主视角”“作为悬念”）；这类内容不进入 JSON 的展示字段，HTML 也不显示。

执行口径以本 Skill 与 [SOP V1.3](references/SOP_V1.3.md) 为准；旧版报告不自动改写。

这是"从剧本取事实"的整理工具，不是创作工具：

- 不改写正文，不补充世界观，不设计新外观、服装、场景；不写绘图、TTS、视频或分镜提示词。
- 正文没写明、前后不一致、无法判断的，一律写入 `待确认`，不得猜测补全。
- 音色、BGM、Foley 属于制作建议，与正文事实分层。

## 输入优先级

1. 用户本轮指定的定稿正文与整理范围；
2. 用户当前明确确认的角色、场景、道具事实；
3. 项目纯净记忆（仅用于跨集同一性，不得覆盖正文）；
4. 一般制作常识。

旧稿、废弃大纲、未确认人设与其他项目内容均不得混入。

## 先选运行模式

| 模式 | 情形 |
|---|---|
| `full` | 正文已定稿，首次整理 |
| `delta` | 已有旧清单，正文改动或集号重排：必须带上旧清单，输出变化区和新旧集号对照 |
| `preview` | 正文仍在改，设计端要先开工：只收稳定项，首页标"预研／非正式" |

不确定时问用户一句"正文是否定稿"。细则见 [delta-and-preview.md](references/delta-and-preview.md)。

## 核心判断：三道入库门

候选项通过任一门入 A（预制主资产），并记录是哪一道：

- **R 复用门**：多镜头或多集出现，重生成会造成观众可见的漂移。
- **E 证据门**：后续要比对同一物的文字、纹样、伤痕、位置、页序或持有人，镜头再少也入库。
- **D 难生成门**：即使只出现一两次，属于难生成类型（文字与版式、复杂空间／机关、非常规姿态、多步特效／变形、群像与精确数量、非常规形态），并且写得出具体失败表现。

D 门的存在是因为"保持一致"和"保证出得来"是两种价值：前者做完整资产包，后者往往一张参考页就够。**重要不等于难**：特写一次、剧情关键、导演在意，都不构成入库理由。判断问法和类型表读 [gates-and-taxonomy.md](references/gates-and-taxonomy.md)。

没通过任何门的，记 B（场景级参考，一段戏内统一方位或页序）或 C（镜头内生成），简记在"非预制项"里，不计数。

## 工作方式

1. **锁范围与模式。** 先建场次索引写入 `meta.scene_index`；每个结论带至少一个来源定位，如 `E03-2`。
2. **建命名登记。** `meta.naming_registry` 列出规范名与禁用写法，之后一律用规范名。这是为了防止同一职业、同一物件出现两种叫法，流到制作端会被当成两个东西。
3. **逐项过三门。** 对每个候选项写通过的门及理由；对所有文字载体（文书、短信、屏幕、标签）和特殊形态（灵魂、变形、拟人动作、多步特效）额外做一轮 D 门扫描，这类项最容易被"复用门"漏掉。
4. **写预制形态。** 每条 A 写 `deliverable_spec`：做什么（`forms`）、必须包含哪些正文已写元素（`must_include`）、`light` 或 `full`。只写做什么，不写外观设计。
5. **角色状态卡。** 只为跨镜头／跨集反复出现且需固定外观的状态建立；服装、遮挡、伤妆、特效是核对维度，不是自动拆卡理由。正文没写换装就不虚构"办公室装／手术装"。
6. **道具归类。** `asset_type` 必填：证物道具、规则视觉、版式包、形态素材。同类器械不等于同一证物；固定机关和陈设并入所属场景。
7. **条件可见锚点。** 默认看不见、只在特定镜头出现的特征，记 `visibility: conditional` 与 `visible_when`，并在连续性备注写明其他镜头不得露出。
8. **旧清单复核。** 列出保留、升级、降级、移除、来源移位，并给理由，旧条目不得悄悄消失。
9. **连续性风险。** 只报资产层问题：状态矛盾、进入方式／时间不一致、道具突然出现或消失、损坏状态未恢复、称呼漂移。每条给最小确认动作，不自行修剧本。
10. **声音建议（默认提供）。** 在事实资产之后增加，声音库不计入视觉资产数量：
    - **人物音色**：每个有台词的角色一条，标 `role_tier`（主角／配角／群声）；写声线方向、状态切换（带来源场次）、避免事项。不以未确认的外貌推导声线，不指向在世演员。
    - **固定 BGM**：判断哪些场景或规则视觉会反复出现、适合配固定主题，每首写 `recurrence`（固定主题／段落氛围）、`scene_ids`（适用的场景或规则视觉资产）、风格与配器、BPM 或节拍感、进入与退出点、避免事项。只出现一次或需要静默的场景不硬配。
    - **场景与固定 BGM 对照**：由 `scene_ids` 自动生成，没有固定 BGM 的场景会标明。
    - **按集调用点**：具体哪一场、什么时候进、什么时候退、配什么环境声；不配 BGM 的段落把 `bgm_id` 留空并写明用拟音代替。
    - 经文、歌曲、成品录音标授权待确认并给原创替代方向；不用具体成品歌曲名。
11. **校验再渲染。** 先生成符合 [schema.md](references/schema.md) 的 JSON，然后依次运行：

```bash
python3 scripts/validate_inventory.py <inventory.json>
python3 scripts/render_asset_inventory_html.py <inventory.json> --out <inventory.html>
```

校验有错误就先修；警告要逐条看过。同时输出供留档的 Markdown 摘要，数量与 HTML 一致。

## 常见边界情形

实测中反复遇到，按此处理（完整说明见 SOP 第 5 节“常见边界情形”）：

- 正文里的 PS／制作标注若写了视觉描述，可作 `must_include` 来源，但要在待确认里注明“来源为制作标注”。
- 范围内只有名字或声音、没有画面的对象，记为非预制，去向写“暂缓：范围内无出镜／可见形态未写明”，并写 `revisit_when`。
- 范围内只出现一次、看不出后续是否比对的项，按“拿不准降 B”处理并写重评条件，不引用范围外内容；下一轮用 `delta` 复核。
- 无标头的转场用 `E04-2b` 这种字母后缀；一个标头含多个地点时拆成 `E08-1a`、`E08-1b`。
- 规则视觉按“设计端是否要做两套”判断是否拆分，不按出现位置拆。
- R 门资产确需 `light`（如背景群演）时，必须写 `weight_note`。
- `naming_registry.banned` 写带上下文的错误短语，不写常用词本身。

## 提取准则（要点）

- **写完逐句自查一个问题：这句话会改变设计端要做的东西吗？** 不会就删。校验脚本只能拦住剧情功能字段，拦不住写进锚点、约束和待确认里的评价与剧情解释（如“最容易出错的戏”“作为悬念”），这一步要靠执行者自己把关。

- **锚点只写画面上看得见的特征**，不带场次编号、剧情说明或身份标签（来源写在 `source_refs`，剧情写在 `dramatic_function`）。否则设计端会把剧情信息当成外观要求。
- **角色**：只记正文已出现的称谓、职责、可见外观、状态、关系。没有文字依据，不补年龄、脸型、配色、性格标签。
- **场景**：优先跨集复用，或单集多镜头必须保持方位的空间。每个主场景写 3—5 个**可见、可核对**的锚点；"压抑""高级"等抽象形容词不是锚点。多子空间写成场景包并附 `space_plan`。
- **叙事道具**：记它服务的行动／线索、持有人、可见状态、后续是否复用。
- **规则视觉**：能力特效、数值界面等反复调用的效果归此类，不叫手持道具。

## 交付格式

默认交付：

- `<项目名>_制作前资产清单_Vx.x.json`：唯一结构化事实源；
- `<项目名>_制作前资产清单_Vx.x.md`：便于归档与审阅；
- `<项目名>_制作前资产清单_Vx.x.html`：桌面端预览。

HTML 的阅读顺序：

1. **首页**：主资产数量（按角色／场景／道具类）、轻量参考数、非预制项数、待确认数、入库门分布，然后是**制作总表**（一行一个资产：类别、入库门、预制形态、做到什么程度、出现范围、待确认数）。
2. **角色／场景／道具**：每个资产一张可折叠卡片，只含入库理由、预制形态与必须包含项、最可能出的错、可见锚点、状态卡、制作约束、待确认。不含剧情功能。
3. **不预制**：去向、原因、何时重评；`delta` 模式再加“相对旧版变化”。
4. **按集新增**与**资产连续性待确认**。
5. **声音建议**：人物音色（主角、配角、群声分层）、固定 BGM 建议、场景与固定 BGM 对照、按集调用点、声音待确认。

不要在 HTML 内显示提示词、模型设置、分镜或未经确认的视觉设计稿。

## 版本纪律

每次结构或提取标准变更都更新本文件 `version` 与 [CHANGELOG.md](CHANGELOG.md)。同一版工具对不同剧本生成的报告，使用各项目自己的报告版本，不反向修改 Skill 版本。示例清单见 `assets/example_inventory.json`，可作为新项目的起点。
